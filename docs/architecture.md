# 运行时架构

MCP HTTP 和 stdio 共用服务实现以及带版本号的工具契约。业务、控制和管理 HTTP 监听器各自使用容量受限的工作线程池。MCP HTTP 工具调用使用同一业务并发额度。HTTP 与 stdio 根据握手结果生成本会话的工具元数据和结果。每个 stdio 进程有独立的服务实例、随机身份和私有临时缓存。关闭 stdin 时，该实例会取消正在执行的任务并清理临时数据。协议输出写入 stdout，日志写入 stderr。

各 SQLite 连接均由专用 Qt 线程管理。搜索缓存键和搜索任务的合并条件包含客户端身份、实际生效的后端配置和缓存结构版本。网页缓存键包含客户端身份，切换后端后仍然有效。正在进行的搜索如果还有至少一半的完整搜索时限，相同请求即可合并到这次搜索中。等待者各自使用独立的截止时间。最后一个等待者离开或共享截止时间到期时，上游请求即停止。上游请求比等待者最多提前一秒结束，以便把已经取得的 SearXNG 结果作为 `partial` 返回。服务先返回结果，再异步写入搜索缓存。

<a name="settings-and-sources"></a>

## 设置与搜索后端

监听地址等部署配置在重启后生效。MSI 或 DEB 安装的服务会加载可执行文件旁的 `data/runtime.json`。便携版可使用同样的默认路径，也可以显式指定配置文件路径。`project_version` 将运行时配置文件与可执行文件的发布版本绑定。用户设置、后端密钥、凭据和缓存都归其所在的部署管理。设置存储会发布不可变的设置和搜索源凭据快照。管理 API 通过原子操作写入已验证的更新，并检查修订版本是否匹配。每项执行中的操作都会继续使用操作开始时的快照。守护进程每两秒检查搜索设置文件的变更。首次启动时，已有设置或密钥文件未通过验证会阻止启动。热重载失败时继续使用上一次有效的快照。搜索后端密钥保存在独立的受保护文件中。

首次保存客户端授权时，服务以 `runtime.json` 的 `clients` 为初始列表，将完整列表及本次变更写入 `settings.directory/client-registry.json`。此后以注册表为准。通过管理页新增、轮换或删除凭据会在持久化成功后立即发布授权快照。CLI 写入供下一次启动加载，运行中的管理页会报告 `pending_restart`。页面读取当前磁盘修订后再保存，会应用完整注册表，包括待加载的 CLI 更新。使用过期修订写入会返回冲突。管理页或 CLI 保存手动授权时，将原文 `token_value` 和认证摘要 `token_sha256` 原子写入受限注册表。加载时验证两者一致，认证使用摘要。注册表也支持文件和环境变量来源，容量上限为 2 MiB。轮换保持客户端缓存身份，删除后重建则分配独立的身份和会话。

管理会话经同源和 CSRF 校验后，才可按需读取单个授权码。列表和业务接口不返回原文。手动授权的可恢复原文受文件权限保护，备份应使用相同的访问控制。仅保存摘要的凭据可用于认证，无法从摘要还原原文。

设置监听器默认使用回环端口 3183。若端口已被占用，软件包初始化时会记录一个可用端口。网页应用由服务程序内嵌的 Qt 资源提供。独立的管理凭据可用于直接登录，也可用于签发浏览器的一次性登录链接。会话保存在内存中。设置写入受 Host 和 Origin 白名单、会话 Cookie 和 CSRF 请求头约束。参见[管理 API](api.md#administration)。

执行工具前，服务会检查搜索和打开网页的开关。QGIS 插件将初始化、工具发现和工具调用通过 MCP 转发至公网服务，并转发客户端提交的业务 Bearer，不增加搜索审批。Manager 的本机 relay 健康检查使用独立凭据，仅反映插件自身是否就绪。远端离线会使实际 MCP 请求失败，但不会被误判为本机进程故障。原生服务的状态工具只读取本地信息和上次观测到的搜索源状态，无需访问搜索后端。

后端注册表在 `auto` 模式下选择 DuckDuckGo HTML、DuckDuckGo Lite 和 Bing 备用来源，也可以选择已配置的 SearXNG、Brave、Tavily、Exa、Perplexity 或 DeepSeek 后端。所有搜索结果都经过共用的筛选、去重和标准化流程。自动模式会限制请求频率，并在触发限制后暂停一段时间。搜索后端的设置和凭据独立于客户端的业务令牌。

<a name="outbound-http-and-tls"></a>

## 出站 HTTP 与 TLS

libcurl 使用 c-ares 解析地址。访问公开的搜索源和网页时，服务会检查实际连接的地址和每次重定向的目标。由管理员固定配置的 SearXNG 端点适用私有后端策略。运行时流量不沿用系统或环境变量中的代理配置。构建下载使用的代理只对构建工具生效。

TLS 在 Windows 上使用 Schannel，在 Ubuntu 上使用发行版提供的 OpenSSL，以验证主机名和证书链。Schannel 默认使用 Windows 信任库。私有后端可以配置自己的 CA 文件。Windows 上的 TLS 测试观察到，当缺少中间证书时，系统会通过 AIA 获取中间证书。部署端点时应提供完整的证书链。管理员可通过 Windows 的 `MaxAIAUrlRetrievalCountPerChain` 设置管理 AIA 获取行为。两个平台的测试都验证了不会向网络发起 CRL 或 OCSP 查询。Ubuntu 测试还验证了不会发起 AIA 获取请求。

经哈希校验的 cpp-httplib 补丁为请求读取设定两秒的总时限，涵盖请求头、正文、分块传输的帧结构和尾部字段。应用操作另有各自的截止时间。关闭服务时会中断所有已接受的连接，包括仍在等待工作线程的连接。

## 入站 HTTPS

业务监听器默认在回环地址提供 HTTP。配置 `business.tls` 后，cpp-httplib 在同一端口使用 HTTPS 提供 MCP。Windows 使用静态链接的 Mbed TLS 3.6.8，Ubuntu 使用系统 OpenSSL。证书链与私钥在检查配置和启动服务时加载，更换证书后需重启。控制和管理监听器继续在独立的回环端口提供 HTTP。[部署与证书配置](deployment.md#windows-cloudflare-tunnel)
